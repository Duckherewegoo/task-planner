# ADR-0007: Python 3.14+ 作为最低版本

- Status: Accepted
- Date: 2026-10-07（commit `2395ff1`，"尝试升级到 python 3.14，试验新特性"）
- Related:
  - `pyproject.toml`：`requires-python = ">=3.14"`，及 black / ruff 的版本注释
  - 例外：`good_addons.py` 保持 3.10 兼容（见下）

## Context

个人项目，无外部用户，主要价值是"把新语言特性用起来"。
2026-10 时 Python 3.14 已发布，具备 `StrEnum`、`NotRequired`、
PEP 649（延迟注解求值）、PEP 695（泛型语法）等特性。

## Decision

**最低版本定为 Python 3.14**，全项目使用新语法。

## Alternatives Considered

- **A. 3.12（当时事实上的 LTS 生态位）**：否决。3.14 的新特性对代码可读性收益明确
- **B. 3.13**：未评估。与 3.14 差距小，无明显理由选 3.13 而非 3.14
- **C. 3.10（最大兼容）**：否决。代价是新语法全部不可用，收益（兼容性）对个人项目无意义
- **D. 3.14**：采纳

## Consequences

**正面**

- `StrEnum` 用于状态枚举，`NotRequired` 用于 TypedDict 可选字段
- PEP 695 泛型语法更简洁
- 直接用最新标准库，无版本条件编译

**负面（接受的代价）**

- **用户群极窄**：3.14 发布初期的用户几乎只有尝鲜者。
  对个人项目可接受，若未来开源分发会成为门槛
- **工具链滞后**：`black` 需 25.x 才支持 `target-version = py314`
  （pyproject 里有注释说明"如报错降为 py313"）
- **依赖兼容风险**：部分第三方库可能未适配 3.14，
  目前核心依赖（LangGraph / Dash / pymongo / openai）均正常

**遗留**

- **`good_addons.py` 是例外**：它是"可复制到任何项目的 drop-in 库"，
  保持 3.10 兼容，因此 `ruff` 里 `UP047`（PEP 695 泛型）被全局 ignore。
  这是"项目下限 3.14"与"drop-in 库下限 3.10"并存的代价
